How I work

Five working principles

  1. 01

    Dependencies on day zero

    Any feature that touches more than one service gets a dependency map before the sprint starts, not halfway through it.

  2. 02

    Every sprint has a cut list

    We agree up front what we drop first if time gets tight, so a slip is a decision, not a surprise.

  3. 03

    Success is defined before we build

    Every feature starts with the metric it should move, and we check that metric after we ship.

  4. 04

    Decisions go in writing

    Options, criteria and the decision are written down before we build, so nobody re-argues it three sprints later.

  5. 05

    Nothing ships blind

    Logs, metrics, alerts and a runbook before production, and a rollback path before launch.
